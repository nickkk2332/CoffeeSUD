# CoffeeSUD documentation audit, November 2026

Part of the [audit folder](README.md). Linked from the [creator handbook](../docs/creator/README.md).

## Introduction

In November 2026 the creator handbook (`docs/creator/`, chapters 01 to 33) was rewritten chapter by chapter, and each chapter was then checked against the Java by a second pass (verification). Both passes kept notes. This report collects what those notes found that is not a handbook problem: code that does not do what its own help, javadoc or obvious intent says, and shipped text that disagrees with the code.

The report holds:

1. [Engine defects](#engine-defects), IDs `D-<area>-<n>`.
2. [Help and comment mismatches](#help-and-comment-mismatches), IDs `H-<area>-<n>`.
3. [Inherited guide differences](#inherited-guide-differences).
4. [Not verified](#not-verified).
5. [Suggested next steps](#suggested-next-steps).

How to read it. Each defect names the file and line, what the code does, what was expected, a severity, and the handbook chapter that documents the real behaviour. Severity: **high** silently breaks content or loses data; **medium** a documented option does nothing or misbehaves; **low** cosmetic or edge case. Java paths are relative to `CoffeeMud/com/planet_ink/coffee_mud/` unless they start with `tools/`, `audit/`, `docs/` or `CoffeeMud/`. Line numbers were taken from the notes and re-checked for the high-severity items; others may have drifted by a few lines.

The handbook already documents the real behaviour wherever it differs from the code's stated intent, and warns about the traps below. Nothing here was fixed in the engine. Where a verifier corrected a writer, or the integration pass corrected both, this report follows the later conclusion. Almost nothing was run: a few verifiers called individual parsers directly or compiled the engine-programming chapter's example classes, and the first-world tutorial's own playtest was run in a scratch world (see its chapter's findings); everything else was read from code. Items marked "not run" were read from code only.

Area codes: BW building and world files, SC scripting (MOBPROG), JS JavaScript, PR properties, BM behaviors and masks, IC items and crafting, AB abilities, CH characters and progression, QU quests, SE society and economy, WS world simulation, TI travel and instances, SP saves and party, GE generation, DT developer tools and scripts, CF configuration, ES engine structure (class loading, messages, ticking, build files).

## Engine defects

### Building and world files

- <a id="d-bw-1"></a>**D-BW-1. MODIFY MOB ... LEVEL always re-fills the mob's stats.** `Commands/Modify.java:2912` (`mobs()`, end). The test `(!mob.isGeneric())&&(modMOB.basePhyStats().level()!=oldLevel)` checks the builder (`mob`), which is never generic, so `fillOutMOB` runs after every level change, including on generic mobs, overwriting hand-set attack, damage, armor, speed, hit points, mana, move and money. Expected: test `modMOB`. Severity: **high**. Handbook: [21][c21], [01][c01]. **Fixed:** the test is on the mob being edited; a generic mob's attack, damage, armor and speed are re-derived only while they are its class defaults or what its old level gave it, otherwise kept with a message (`Modify.combatStatsUntouched`). Test: `tools/fixtures/fixes/audit-high.js` (bw1-*).
- <a id="d-bw-2"></a>**D-BW-2. CATALOG DELETE skips the confirmation when more than 10 entries match.** `Commands/Catalog.java:632` and `:645` (`del.length>10||confirm`). Handbook: [02][c02]. **Fixed:** a delete of more than one entry asks once for the whole set (count, mobs, items, in use); NO deletes nothing. Test: audit-high.js (bw2-*).

- <a id="h-es-1"></a>**H-ES-1.** `Behaviors/interfaces/Behavior.java:96` and `core/interfaces/Environmental.java:147` say `parmsFormat()` / `miscTextFormat()` "will use the CMParms.MTFORMAT_*" constants.
