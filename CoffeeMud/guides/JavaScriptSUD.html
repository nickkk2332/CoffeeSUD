JavaScript in CoffeeSUD

JavaScript runs in a script's <SCRIPT> block, in JRUN files and JCONSOLE, in quests and cron jobs, in world/js/init.js, and in JavaScript classes. Every one of these scopes gets the same things, listed here. For MOBPROG scripts, see Scripting in CoffeeSUD; in the game, HELP JS has the short form, and JS ERRORS lists what went wrong.

In every scope

  • cm: the game's objects. See below.
  • sud: short names over cm for time, the party, the save, finding things and variables.
  • require('name'): a library from world/js/lib/, or else resources/js/lib/.
  • include('path'): runs a file in this scope.
  • debug(x): writes x to the developer log (DEVLOG) in builder and developer games. In a normal game it does nothing.
  • importPackage(Packages.com.planet_ink.coffee_mud.core) and importClass work, so that a class can be named without its package.

JCONSOLE also has here (its user's room), area and target (who its user fights), set again for each line.

JCONSOLE @blacksmith (or @here, @area, @me, or an item's name) binds a console to that thing: its MOBPROG calls (MPECHO('...')) run as it, with the builder as source, and me, here and cm are its. Lines that start with a dot are the console's own:

  • .trigger SPEECH repair my sword (or GREET, GIVE item, LOOK, TICK): the event, as if it happened, for the target's JScriptable and scripts.
  • .inspect expr: a thing's name, class, room and stats; a JavaScript object as JSON (.inspect cm.store(me)).
  • .load file, .reset (a new scope), .time on|off, .history, and !n to run line n again. In builder mode the history is kept from one game to the next.

cm

The members return the game's own Java objects, so their methods can be called too. The host is what the script runs for: a script's host, or the user of JRUN or JCONSOLE. A room, area or mob given as null means the host's.

cm.on

cm.on(event, function [, key]) runs the function when the event comes, and returns its key; cm.off(key) takes it away, and cm.listening([event]) lists what listens. A listener with the key of an earlier one replaces it. Without a key, the function's own text is its key, so a <SCRIPT> that registers the same function each time it runs keeps one listener. Listeners are not saved: register them in world/js/init.js's onBoot.

  • hour, daypart, day, month, season, year, weather: in the player's area, as the clock and the weather change. The function gets (area, was, now).
  • newgame, restore, save, newchar, switchto, switchfrom, pause, resume, timemode: as GAME_PROG. The function gets (character, detail). A save listener that returns false refuses the save.
  • tick: every tick.

And what happens in the world, wherever it happens:

  • death (victim, killer); beforeDeath (victim, killer), where false keeps the victim alive, at 1 hit point.
  • levelUp (mob, level), once the level is gained.
  • questWin (mob, quest); questEnd (quest, mob, why).
  • enterRoom (mob, room, from); beforeEnterRoom (mob, room, from), where false keeps the mover out; enterArea (mob, area, from).
  • itemGained (mob, item) and itemLost (mob, item), as a mob in a room gets or loses a thing.
  • factionChange (mob, faction, change).
  • turn (leader, count): each step of turn-based time.

Event names are in any case: enterRoom and enterroom are the same. cm.off(event, fn) takes away a listener added without a key.

// world/js/init.js: at 50 orcs killed, the warlord comes
function onBoot() {
  cm.on('death', function(victim, killer) {
    if (killer == null || !sud.party.isMember(killer) || victim.Name().indexOf('orc') < 0) return;
    var w = cm.store('world');
    w.orcKills = (w.orcKills || 0) + 1;
    if (w.orcKills == 50) cm.loadMob('Orc Warlord', cm.room('Fort#1'));
  }, 'orcCount');
}

cm.store

cm.store(key) is a plain JavaScript object kept with the game: what a script puts in it is saved with the game as JSON, and is there again after a restore. key is 'world' (also cm.store()), 'quest:name', any string, or a room (keyed by its ID), a mob (by its start room and name), an item (by where it is and its name) or an area. cm.storeKey(x) gives the key, cm.stores() lists them. A new game starts from world/js/state.json if the world has one: {"world": {"gold": 0}, "quest:smith": {"orders": []}}.

A store keeps data: numbers, strings, true and false, arrays and objects of them. A function or a game object (a mob, a room) is not saved; keep its name or room ID instead. In builder mode, JS STATE lists the stores, JS STATE key shows one, JS STATE key = {gold: 5} replaces it, and JS STATE key DELETE takes it away.

// a smith's <SCRIPT>: an order, due on day 12, still due after SAVE and RESTORE
var orders = cm.store(cm.host());
orders.list = orders.list || [];
orders.list.push({who: source.Name(), item: 'longsword', readyDay: cm.clock().day() + 3});

sud

  • sud.time: now(), isTurnBased(), advance(ticks), passTime(hours [, area]), waitUntil(test [, then]) (test runs each tick until it returns true; then, if given, runs once after).
  • sud.party: leader(), members(), isMember(mob).
  • sud.save: slot(), isBuilder(), isDev().
  • sud.find: room(id), mob(name [, area]), item(name [, room]).
  • sud.vars: get(holder, name), set(holder, name, value), list(holder).
  • sud.on(event, fn [, key]) and sud.off(key), as cm.on.

Effects in JavaScript

The property Prop_JScript (for mobs, items, exits, rooms and areas) and the behaviour JSBehavior run a file: SCRIPT=world:js/props/bloodblade.js KILLS=0. The file is compiled once while it is unchanged, and run in a scope of its own for each property or behaviour. The other parameters are the file's parms, numbers as numbers; what a hook changes in parms is written back to the property's text, so that it is saved with its host. The scope has CMMsg, and all that every scope has.

HookProp_JScriptJSBehavior
affectPhyStats(host, affected, stats)yes
affectCharStats(host, mob, stats)yes
affectCharState(host, mob, state)yes
okMessage(host, msg): false refuses ityesyes
executeMsg(host, msg)yesyes
tick(host, tickID)yesyes
onAdded(host), onRemoved(host)yesyes

The stat hooks run each time the host's stats are worked out: keep them quick, and change parms in the others. A hook that fails is listed by JS ERRORS, and not called again until the text is set again.

// world/js/props/bloodblade.js: 1 damage for each 10 kills
function affectPhyStats(host, affected, stats) {
  if (affected == host) stats.setDamage(stats.damage() + Math.floor(parms.KILLS / 10));
}
function executeMsg(host, msg) {
  // a death message's tool is the killer
  if (msg.sourceMinor() == CMMsg.TYP_DEATH && host.owner() != null && msg.tool() == host.owner()) {
    parms.KILLS++;
    host.recoverPhyStats();
  }
}

JScriptable

The behaviour JScriptable scripts a mob, item, room, exit or area wholly in JavaScript. Its parameters are LOAD=world:js/npc/ferryman.js (with SCOPE= if wanted), or the script itself. The script defines the handlers it wants; only those are called.

HandlerWhen
onLoad()the behaviour is added (and the game loads its host)
onGreet(who), onLeave(who)someone comes into or leaves the host's room (any room of an area)
onArrive(room)the host itself comes into a room
onSpeech(who, text)someone says something
onGive(who, item)someone gives the host a thing
onGet, onDrop, onWear, onRemove (who, item)someone gets, drops, wears or removes a thing
onOpen, onClose, onLock, onUnlock (who, thing)someone opens, closes, locks or unlocks a thing
onDeath(killer), onKill(victim)the host dies, or kills
onDamage(who, amount)the host is hurt
onCast(who, ability, target)someone casts
onLook(who)someone looks at the host
onTick(), onHour(hour), onDay(day)each tick, and as the host's area's clock changes
onCommand(who, verb, rest)someone near the host types a command, before the game's own: true handles it
canMessage(msg), afterMessage(msg)before any message (false refuses it), and after
onReload(old)after JS RELOAD, with the old scope

Its other functions can be called from MOBPROG: MPCALLFUNC fare 5 and CALLFUNC(fare 5) on the host's own script, or MPCALLFUNC $i fare 5 for another host's. A function gets the arguments as one string and the caller, and what it returns is CALLFUNC's value.

The scope has me (the host), cm (with cm.host() the host), state (the host's cm.store, saved with the game), CMMsg, and all that every scope has. SCOPE=INDIVIDUAL, the default, gives each host a scope of its own; SCOPE=GLOBAL or a name shares one scope among the hosts that give it, with me and cm set for each call and state the store scope:name.

// world/js/npc/ferryman.js
function onSpeech(who, text) {
  if (('' + text).toLowerCase().indexOf('ferry') < 0) return;
  cm.say(me, 'Five coins, ' + who.name() + ', and we cross.');
  state.waiting = '' + who.Name();
}
function onGive(who, item) {
  if (state.waiting == '' + who.Name() && item.Name().indexOf('coin') >= 0) {
    state.crossing = {who: state.waiting, ticks: 3};
    cm.say(me, 'Hold on.');
  }
}
function onTick() {
  if (state.crossing && --state.crossing.ticks == 0) {
    cm.cmd(cm.findMob(state.crossing.who), 'east');
    state.crossing = null;
  }
}

Shared code

require('name') loads a CommonJS module: it sees only exports and what it requires, and gives back exports. include('path') runs a file in the scope that calls it, so what it defines stays there: path is under resources/, or world:path is under the world folder; .. is refused. Both compile a file once and read it again when it changes.

Reloading

In builder mode, JS RELOAD puts the files of world/js changed since the game started (or since they were last reloaded) into the running world: JS RELOAD props/ferry.js reloads one, JS RELOAD ALL every one. A file that does not compile is shown with its line, and left as it was. Then:

  • init.js is read again, and its onReload(old) called with the old file's scope (its onBoot is not run again);
  • a library in lib/ is read again where it is required from then on (a scope keeps what it has already required);
  • a class (in behaviors/, properties/ and the other class folders) is compiled again; its behaviours and effects in the world are replaced with new ones, their text kept, and the mobs, items and rooms made from then on use it;
  • any other file (Prop_JScript's and JSBehavior's) is read again by each one running it, which calls its onReload(old) with the old scope.

JS WATCH ON (with a number of seconds, 3 if none) does it by itself as files change; JS WATCH OFF stops it.

// world/js/props/ferry.js: a crossing half done carries over a reload
var crossing = null;
function onReload(old) { crossing = old.crossing; }

Examples

var g = cm.loadMob('Town Guard', cm.room('Town#1'));
cm.say(g, 'Halt, ' + cm.player().name() + '!');

// world/js/init.js
function onBoot() {
  cm.on('daypart', function(area, was, now) {
    if (now == 'night') cm.echo(cm.room('Town#1'), 'The lamplighter makes his rounds.');
  }, 'lamplighter');
  cm.on('save', function(who, slot) {
    return cm.var('*', 'INBOSSFIGHT') != 'yes';   // no saving in the boss fight
  }, 'noBossSave');
}

// a guard's <SCRIPT>: a warrant for anyone carrying the idol out of town
var law = cm.law();
if (law != null && cm.findItem('golden idol', source) != null)
  law.accuse(source, 'theft');
